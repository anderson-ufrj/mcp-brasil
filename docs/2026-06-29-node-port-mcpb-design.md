# mcp-brasil — Node/TypeScript Port + MCPB Bundle

## Goal

Port the Go implementation of `mcp-brasil` to **Node.js + TypeScript** and package it
as an **`.mcpb` Desktop Extension** to submit to Anthropic's MCPB directory (featured
local extensions for Claude for macOS/Windows).

The Go server stays in the repo as legacy; Node becomes the official, submittable
implementation. Directory requirements drive the stack choice: **public GitHub repo,
MIT license, built with Node.js, valid `manifest.json` with `author` → GitHub profile.**

## Scope — v1 (10 tools, zero config)

| Domain | Tools | API base |
|--------|-------|----------|
| **BCB** (4) | `bcb_selic`, `bcb_ipca`, `bcb_exchange_rate`, `bcb_indicator` | api.bcb.gov.br |
| **IBGE** (3) | `ibge_states`, `ibge_municipalities`, `ibge_population` | servicodados.ibge.gov.br |
| **CNPJ** (1) | `lookup_cnpj` | minhareceita.org |
| **PNCP** (2) | `pncp_contracts`, `pncp_modalities` | pncp.gov.br |

Keep the `docs://api-reference` resource, updated to reflect only these 10 tools.

### Tool signatures (port 1:1 from Go)

- `bcb_selic(last_n=30)`
- `bcb_ipca(last_n=12)`
- `bcb_exchange_rate(currency="USD", date?="MM-DD-YYYY")`
- `bcb_indicator(indicator!, last_n=30)` — selic, selic_monthly, ipca, igpm, cdi
- `ibge_states()`
- `ibge_municipalities(state_id?)`
- `ibge_population(location_id?)`
- `lookup_cnpj(cnpj!)` — 14 digits, with/without formatting
- `pncp_contracts(start_date!, end_date!, state?, modality=6, page=1)` — dates YYYYMMDD
- `pncp_modalities()`

### Out of scope (YAGNI)

Portal da Transparência (6 tools + `TRANSPARENCY_API_KEY` → v2), CI/CD, registries
beyond the directory, new tools, behavioral changes to existing tools.

## Repo structure (coexistence)

```
mcp-brasil/
├── go/            # current Go code moved here, intact (legacy)
│   ├── cmd/ pkg/ go.mod go.sum ...
├── node/          # new implementation — this folder IS the MCPB bundle root
│   ├── src/
│   │   ├── index.ts        # entry: create server, register tools/resource, stdio
│   │   ├── http.ts         # fetch helper (timeout, standardized errors)
│   │   ├── clients/        # bcb.ts ibge.ts cnpj.ts pncp.ts — pure HTTP, MCP-agnostic
│   │   └── tools/          # bcb.ts ibge.ts cnpj.ts pncp.ts — zod schema + handler + format
│   ├── manifest.json       # MCPB manifest (author → anderson-ntlabs)
│   ├── package.json
│   ├── tsconfig.json
│   └── dist/index.js       # single bundle (generated by esbuild)
├── README.md      # updated: Node section (official) + Go section (legacy)
└── LICENSE        # MIT (unchanged)
```

**Boundary rationale:** `clients/` know nothing about MCP — they take params, hit an
HTTP API, return parsed JSON. `tools/` own the zod input schema, call a client, and
format the MCP result. Each is unit-testable in isolation.

## Tech stack

- **`@modelcontextprotocol/sdk`** (official TS SDK) — replaces `mark3labs/mcp-go`
- **`zod`** — tool input schemas (validation + inferred types)
- **Native `fetch`** (Node 18+) — no axios
- **`esbuild`** — bundle `src/` → `dist/index.js`, deps inlined (small MCPB)
- **`@anthropic-ai/mcpb`** CLI (`mcpb pack`) — produces the final `.mcpb`
- Transport: **stdio** (same as Go)

## manifest.json — critical fields

```jsonc
{
  "manifest_version": "0.1",
  "name": "mcp-brasil",
  "version": "2.0.0",
  "description": "Brazilian government & economic data for Claude (BCB, IBGE, CNPJ, PNCP).",
  "author": { "name": "Anderson H. da Silva", "url": "https://github.com/anderson-ntlabs" },
  "license": "MIT",
  "server": {
    "type": "node",
    "entry_point": "dist/index.js",
    "mcp_config": { "command": "node", "args": ["${__dirname}/dist/index.js"] }
  },
  "tools": [ /* the 10 tools above, name + description */ ]
}
```

No `user_config` — zero config reinforces one-click install (a directory plus).

## Error handling

Mirror Go behavior: tool handlers catch client errors and return an MCP **tool error
result** (not a thrown exception), so the model sees a readable message. `http.ts`
centralizes timeout + non-2xx → typed error. Invalid required inputs are rejected by
zod before reaching the client.

## Testing

- **Vitest** unit tests per client with mocked `fetch` — validate parsing of real
  BCB/IBGE/CNPJ/PNCP payload shapes (capture sample responses as fixtures).
- **Smoke test**: boot the server, list tools via an MCP client, assert the 10 tools +
  the `docs://api-reference` resource are present.
- **Manual gate**: `mcpb pack` → install the `.mcpb` in Claude Desktop → call one tool
  per domain end-to-end before submitting.
